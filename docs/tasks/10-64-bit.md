# Task 10: 64-bit

Handover. Read `docs/PLAN.md`, `docs/design.md` ("Pointer width", the
measurements and why 32-bit came first), `docs/tasks/01-game-c-builds-
for-host.md` (its Rules section applies unchanged) and

## Why now

The port plays and releases at i686. 64-bit is what a macOS build and
ARM64 Linux (Raspberry Pi, ARM laptops) need, and Linux distributions
keep shrinking their 32-bit libraries, which is the Linux release's main
burden today (players install `:i386` packages). The game is complete
on i686, so every 64-bit difference can now be checked against a
working 32-bit build of the same code.

## The goal

`-DLSD_ARCH=x86_64` plays like i686: boots, a whole day, links,
flashbacks, SAVE and LOAD (cards readable by both widths and by the
console: the card format is the PS1's), music, movies, widescreen, with
the i686 build unchanged and lsddecomp byte-exact on the PS1. Then the
64-bit Windows build (MinGW x86_64, LLP64: `long` stays 32-bit there) the
same. i686 stays the release default until the operator switches.

## The task

1. **Static asserts first.** On every layout the disc or the card fixes
   (the TMD header and object table, `TmdObject`, TIM headers, the card's
   save header and blocks, any file struct read in place), assert the
   PS1 size and the offsets that matter, in lsddecomp (they hold on the
   PS1 too). These are the tripwires for everything after.
2. **Get it booting.** Start from the `BMemPMgrAlloc` crash. Likely
   suspects, in order: the pool too small for 64-bit objects (or a
   block header that assumes 4-byte pointers), a hand-sized allocation,
   TMD relocation. Fix the cause, not the symptom, and record each.
3. **The 71 addresses in integers.** Change the type (a pointer, or
   `intptr_t`/`uintptr_t` where an integer slot must carry both) at the
   declaration and the uses. `style_layer.c`'s `s32` scene references
   are most of them. Each is a real truncation at 64 bits; the count
   in CI must reach 0.
4. **TMD data.** At 64 bits the file's 32-bit words cannot hold
   addresses. Decide with evidence between: relocating into a separate,
   pointer-sized table; keeping offsets and resolving at each use; or a
   host-only parallel structure. The choice touches psyz's libgs
   (`GsMapModelingData`, `GsLinkObject4`, `GsSortObject4`) and the
   game's TMD code (`TmdRenderer`, `tmd_model.c`); write it up before
   doing it.
5. **Everything else that shows up**, found by running: the paths
   task 08 drove (`tools/lsd_drive.py`, a whole day, set days from gdb,
   a flashback, SAVE/LOAD, GRAPH), and the sanitizer build at x86_64
   (`-DLSD_SANITIZE=address,bounds` works at both widths). Compare
   screenshots against i686 at the same moments; with the same input
   the two should match exactly, since the game logic is integer.
6. **Windows x86_64** (MinGW): builds, and runs under Wine as task 06
   ran i686 (`docs/tasks/06-release-handover.md`, Wine notes).

## How to work

- Where a fix belongs: **lsddecomp** for the game's C (a topic branch,
  for example `host-64-bit`, with `./build-and-verify.sh` and
  `tools/lint.sh` green: PS1 bytes unchanged), **psyz fork** for the SDK
  (topic branch), **lsd-port** for the build and the platform layer.
  Point `decomp/` and `psyz/` at the topic branches on lsd-port's branch.
- Fixes that keep the PS1 bytes and are right at both widths are the
  rule (types, `sizeof` instead of hand sizes). `#ifdef HOST_BUILD` is
  the last resort and needs the operator's yes, as in task 08.
- Many small commits, each one kind of fix, so the operator can review
  lsddecomp's branch in pieces.
- The i686 build must keep passing everything after every change: run
  a day at i686 too, not only at x86_64.

## Rules (in addition to task 01's)

- **lsddecomp: never commit on `main`.** Topic branch, with
  `./build-and-verify.sh` and `tools/lint.sh` green.
- **Never push to any repo's `main` without the operator's yes** for that
  push. Topic branches you may push. Pins must be on their remotes before
  lsd-port's `main` moves.
- No game data, BIOS, recordings, screenshots or save files in any
  repository.
- No windows on the operator's display: headless or `xvfb-run -a`
  (`~/.claude/CLAUDE.md`).
